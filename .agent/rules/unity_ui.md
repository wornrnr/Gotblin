# Unity UI Development Guidelines

## 1. Prefab-Driven UI (프리팹 기반 UI 작업)
- **절대 스크립트에서 UI 요소를 동적으로 복제(Clone)하거나 생성(`Instantiate`, `new GameObject()`)하지 마세요.**
- 모든 UI 요소(버튼, 텍스트, 레이아웃 등)는 반드시 유니티 에디터에서 해당 프리팹 내부에 직접 배치되어야 합니다.
- 기획자나 디자이너가 유니티 에디터를 열었을 때 눈에 보이는 화면(WYSIWYG)과 실제 게임 화면이 완벽하게 일치해야 합니다. 임시방편(Hotfix)으로 코드에서 UI 레이아웃을 생성하는 꼼수는 금지됩니다.

## 2. Inspector Binding (직렬화 필드 바인딩)
- UI 컨트롤은 스크립트에 `[SerializeField]`로 선언하고, 인스펙터에서 수동으로 드래그하여 연결하는 유니티의 정석적인 방식을 따릅니다.
- 연결되지 않았을 경우(`null`일 경우)를 대비해 코드로 임의의 UI를 억지로 만들어내는 방어 코드를 작성하지 마세요. (비어있다면 개발자가 인스펙터에서 연결하도록 안내하는 것이 맞습니다.)
- 특정 상황(예: 특정 탭 선택 시)에서 UI를 숨겨야 한다면, 프리팹에 미리 배치된 오브젝트의 `gameObject.SetActive(false)`를 호출하여 제어하세요.

## 3. 작업 리스크 고려 사항
- 개발팀 내부적으로 여러 명의 개발자가 동시에 같은 프리팹(`.prefab`)을 수정하지 못하도록 통제 시스템(또는 규칙)이 마련되어 있습니다.
- 따라서 Git Merge Conflict(충돌) 발생 리스크를 이유로 프리팹 수정을 피하거나 스크립트 우회 방식을 제안할 필요가 없습니다. 무조건 유니티 권장 표준 방식(Standard Workflow)을 최우선으로 적용하세요.
